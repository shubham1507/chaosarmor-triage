# GO-012 - Start the ChaosArmor Triage HTTP API

## What changed

Added `-serve` to start a local HTTP server on `127.0.0.1:8080`.
`GET /healthz` returns a JSON response with status 200. An unsupported
method returns 405 and `Allow: GET`. An unknown path returns 404.

## Why

The DevOps team can verify that the API process responds before incident
resources and persistence are added.

## Go concepts

- `http.Server` runs the API and `http.ServeMux` routes requests.
- A handler reads the request method and writes headers and a body.
- `httptest` exercises routing and responses without a listening socket.

## Files changed

- `main.go` adds the server mode flag.
- `server.go` implements the HTTP server, router, and health handler.
- `server_test.go` verifies 200, 405, and 404 responses.
- `docs/development/GO-012.md` documents the change.
- `docs/development/README.md` links this entry.

## Verify

- Run `go test ./...` and `go vet ./...`.
- Run `go run . -serve`.
- In another terminal, run `curl.exe -i http://127.0.0.1:8080/healthz`.
- Expect HTTP 200, JSON content type, and `{"status":"ok"}`.
- Run `curl.exe -i -X POST http://127.0.0.1:8080/healthz`.
- Expect HTTP 405 and `Allow: GET`.
