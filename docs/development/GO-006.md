# GO-006 - Represent an optional request total with a pointer

## What changed

`parseOptionalTotal` returns `nil` for absent or empty input, an error
for invalid input, and a pointer to the parsed integer for a valid total.
The CLI checks for `nil` before reading the total.

## Why

A basic snapshot can omit request volume. Assessment and history need
that volume to interpret the failure counts.

## Go concepts

- `&total` takes the address of the parsed integer.
- `*totalRequests` reads the integer after a nil check.
- Go copies pointer arguments. A copied pointer can still access the
  original value, as `flag.BoolVar(&deployed, ...)` demonstrates.

## Files changed

- `main.go` parses and uses the optional total.
- `docs/development/GO-006.md` records the change.
- `docs/development/README.md` indexes this entry.

## Verify

- `go vet ./...` succeeds.
- `go run .` prints a basic snapshot without severity.
- `go run . -failed-requests 12 -total-requests 200 -history "3,8,8"`
  prints a 6.00% failure rate, warning severity, and two worsened transitions.
- A zero total, history without a total, or failures above the total exits nonzero.
