# GO-013 - Test and publish the Docker image with GitHub Actions

## What changed

Added a workflow that checks formatting, runs `go vet` and race-enabled
tests, builds a Linux container, and verifies the JSON CLI output inside
it. A version-tag push publishes the tested image to GHCR.

## Why

Pull requests get automated checks. A version tag produces an image
that can be pulled and run without a local Go installation.

## Files changed

- `.github/workflows/ci-cd.yml` defines verification and publishing jobs.
- `Dockerfile` builds the CLI and copies it into a minimal runtime image.
- `.dockerignore` excludes Git history, docs, and local build artifacts.
- `docs/development/GO-013.md` records the change and verification.
- `docs/development/README.md` links this entry.

## Verify

- On a pull request or push to `main`, check the `verify` job in Actions.
- The smoke test expects service `checkout`, 12 failures, and
  `recent_deployment` set to false.
- On a version-tag push, check that `publish` succeeds and the matching
  image tag appears in GitHub Packages.

## Scope

The image smoke test covers the CLI. The HTTP server still binds to
loopback inside the container, so host access through `docker run -p`
requires a separate API bind-address change.
