# GO-003 - Assess an incident snapshot

## What changed

Added the optional `-total-requests` flag. When supplied, the CLI calculates
the failure rate, assigns a severity, lists active signals, and suggests a
next check. Omitting the flag preserves the original snapshot output.

## Why

A raw failure count needs traffic volume for context. Twelve failures out of
200 requests represents a different failure rate than twelve out of 20.
Use counts from the same service and observation window.

## Go concepts

- Arithmetic and `float64` conversion preserve fractional rates.
- Comparisons and logical operators validate request counts.
- `if`, `else if`, and `else` classify rates at the 5% and 10% thresholds.
- Bit shifts define signal flags. `|=` sets them and `&` checks them.
- `for range` lists active signals, and `switch` selects a next check.

## Files changed

- `main.go` adds request totals, validation, and assessment output.
- `docs/development/GO-003.md` records the change and verification cases.
- `docs/development/README.md` links this entry.

## Verify

| Command | Expected result |
|---|---|
| `go vet ./...` | Completes successfully |
| `go run .` | Default GO-002 snapshot |
| `go run . -failed-requests 4 -total-requests 100` | Normal severity with no active signals |
| `go run . -service checkout -failed-requests 12 -total-requests 200 -deployed` | 6.00%, warning, both signals |
| `go run . -failed-requests 5 -total-requests 100` | Warning at the lower boundary |
| `go run . -failed-requests 10 -total-requests 100` | Critical at the upper boundary |
| `go run . -total-requests 0` | Nonzero exit |
| `go run . -failed-requests 12 -total-requests 10` | Nonzero exit |
