# GO-004 - Compare failure counts across time windows

## What changed

Added `-history` for earlier failed-request counts in chronological order.
The CLI appends the current count and summarizes changes between windows.
All windows use the same `-total-requests` value. Each historical count
must be a whole number between zero and that total.

## Why

The current severity describes one window. The history shows whether
failures have been rising, recovering, or staying flat.

## Go concepts

- An array fixes the three trend labels and their display order.
- A slice accepts a variable number of observations. `append` adds the
  current count and `windows[1:]` supports adjacent comparisons.
- A map counts transitions by label. Missing labels display zero.

## Files changed

- `main.go` accepts and validates history input before printing the report.
- `history.go` parses failure counts and prints the trend summary.
- `docs/development/GO-004.md` records the change and verification cases.
- `docs/development/README.md` links this entry.

## Verify

| Command | Expected result |
|---|---|
| `go vet ./...` | Completes successfully |
| `go run . -failed-requests 12 -total-requests 200` | Warning with no trend summary |
| `go run . -failed-requests 12 -total-requests 200 -history "3,8,8"` | 0 improved, 1 unchanged, 2 worsened |
| `go run . -failed-requests 2 -total-requests 200 -history "10,7"` | 2 improved |
| `go run . -total-requests 200 -history "3,,8"` | Nonzero exit for an empty history item |
| `go run . -history "3,8"` | Nonzero exit because the total is required |
