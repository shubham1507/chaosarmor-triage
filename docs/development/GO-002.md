# GO-002 - Capture a typed incident snapshot

## What changed

The CLI accepts a service name, a failed-request count, and a recent
deployment flag. It prints a snapshot and can display the field types.
Invalid integers and negative counts produce an error.

## Why

An on-call engineer can capture the same three observations consistently
and repeat the command while investigating a rollout.

## Go concepts

- Static types distinguish the service (`string`), count (`int`), and
  deployment status (`bool`). `:=` infers a type at declaration.
- `var` declarations demonstrate the zero values `""`, `0`, and `false`.
- The package-level `const` defines the fallback service name.
- The parsed count and error have scope within their `if` statement,
  including its `else` block.
- `flag` reads command-line input, and `strconv.Atoi` parses text into
  an integer.
- `fmt.Printf` uses `%s`, `%d`, and `%t` for values and `%T` for types.

## Files changed

- `main.go` handles input, validates the count, and prints the snapshot.

## Verify at GO-002

| Command | Expected result |
|---|---|
| `go vet ./...` | Completes successfully |
| `go run .` | Service `unknown`, count `0`, deployment `false` |
| `go run . -service checkout -failed-requests 12 -deployed -show-types` | Service `checkout`, count `12`, deployment `true`, types `string, int, bool` |
| `go run . -failed-requests twelve` | Validation message and nonzero exit |
| `go run . -failed-requests -1` | Validation message and nonzero exit |
